# 停车场管理数据库：字段设计说明

配套脚本：[停车场管理数据库.sql](停车场管理数据库.sql)，与《01_需求与数据库模型.md》的 8 个实体一一对应。本说明用于核对“字段类型合理性、主外键合理性、约束设计合理性”三个评分点。

## 1. 总体设计约定

| 项目 | 约定 |
| --- | --- |
| 数据库名 | `parking_management_db` |
| 字符集 / 排序规则 | `utf8mb4` / `utf8mb4_0900_ai_ci`（支持中文业务数据；数据库表名和字段名使用英文 snake_case） |
| 存储引擎 | `InnoDB`（支持事务、行锁和外键） |
| 主键 | 8 张表均为单列自增 `BIGINT UNSIGNED AUTO_INCREMENT` |
| 金额 | `DECIMAL(10,2)`，避免浮点误差；月租金额、每小时单价须大于 0 |
| 时间 / 日期 | `DATETIME` / `DATE`，业务时间统一使用 `DATETIME` |
| 状态与类型字段 | `VARCHAR` 加 `CHECK` 约束限定取值，避免无意义的编码表 |
| 外键规则 | `ON DELETE RESTRICT`（历史记录不被物理删除）；更新动作默认 `ON UPDATE CASCADE`，参与 CHECK 互斥约束的 4 个外键列按 MySQL 8.0 限制使用 `ON UPDATE RESTRICT`（见第 3 节说明） |
| 脚本可重复执行 | 重复执行只重建 8 张业务表并重新灌入样例数据，不删除数据库本身 |

## 3. 主外键关系

| 子表 | 外键字段 | 参照父表 | 更新规则 | 删除规则 | 业务含义 |
| --- | --- | --- | --- | --- | --- |
| vehicle | owner_id | vehicle_owner(owner_id) | CASCADE | RESTRICT | 每辆车必须且仅属于一个车主 |
| vehicle | owner_id 上的索引 | — | — | — | 按车主查车时避免全表扫描 |
| charge_rule | created_by_administrator_id | administrator(administrator_id) | CASCADE | RESTRICT | 规则由管理员创建维护 |
| rental_contract | vehicle_id | vehicle(vehicle_id) | CASCADE | RESTRICT | 合同对应一辆车 |
| rental_contract | handled_by_administrator_id | administrator(administrator_id) | CASCADE | RESTRICT | 管理员办理合同 |
| parking_record | vehicle_id / parking_space_id | vehicle / parking_space | CASCADE | RESTRICT | 一次进出场对应一辆车、一个车位 |
| parking_record | charge_rule_id / rental_contract_id | charge_rule / rental_contract | RESTRICT | RESTRICT | 临停关联规则、月租关联合同，二者互斥 |
| parking_record | handled_by_administrator_id | administrator(administrator_id) | CASCADE | RESTRICT | 管理员登记进出场 |
| payment_record | parking_record_id / rental_contract_id | parking_record / rental_contract | RESTRICT | RESTRICT | 缴费归属二选一 |
| payment_record | handled_by_administrator_id | administrator(administrator_id) | CASCADE | RESTRICT | 管理员登记收款 |

> 更新规则取 CASCADE 是因为各表主键为自增值，业务上不会改主键；若日后手工修改主键，引用方自动同步。删除规则取 RESTRICT，保证业务历史记录不会被物理删除。
>
> 例外：停车记录的收费规则ID、月租合同ID，缴费记录的停车记录ID、月租合同ID 四个外键列参与 CHECK 互斥约束。MySQL 8.0 规定带 CASCADE/SET NULL 更新动作的外键列不能用于 CHECK 约束（报错 3823），因此这四列的外键更新动作采用 RESTRICT。由于参照的都是自增主键、业务上从不修改，RESTRICT 与 CASCADE 在实际运行中行为等价，不影响功能。

## 5. 约束汇总

**非空（NOT NULL）**：各表主键、关键标识、外键、时间、状态和金额字段均按要求设为非空；出场时间、停车时长分钟、每日封顶金额、失效日期、备注及二选一归属外键按业务允许为空。

**唯一（UNIQUE）**：车主身份证号、车主电话、车牌号、车位编号、收费规则名称、合同编号、支付流水号、管理员工号、管理员电话、登录账号。

**检查（CHECK，MySQL 8.0.16+ 生效）**：

- 状态/类型取值：车主状态、车辆类型、车辆状态、车位类型、车位状态、停车类型、记录状态、规则状态、合同状态、缴费类型、支付方式、支付状态、管理员角色、账号状态均限定枚举值；
- 金额：每小时单价、月租金额 > 0；实收金额 ≥ 0（待支付为 0，已支付/已退款 > 0）；最低收费、每日封顶金额（非空时）、押金、应收金额 ≥ 0；
- 日期时间：合同结束日期 ≥ 开始日期；收费规则失效日期 ≥ 生效日期（非空时）；出场时间 ≥ 入场时间（非空时）；在场记录的出场时间和停车时长均为空，已出场记录均非空；异常记录的组合暂不限定；
- 互斥：停车记录“临时停车必关联收费规则、月租停车必关联月租合同”；缴费记录“停车记录与月租合同恰有一个非空”且“缴费类型与归属对象一致”。

**参照完整性**：见第 3 节主外键关系。

**支付状态语义**：`待支付` 记录的 `amount_paid` 为 0、`paid_at` 为空；`已支付` 和 `已退款` 记录的实收金额大于 0 且支付时间非空。收入统计只计入 `已支付`。

**跨记录业务约束（由应用层事务/触发器实现，单个 CHECK 无法完成）**：同一车辆同一时刻最多一条未出场记录；同一车位同一时刻最多一条未出场记录；同一车辆生效合同日期不重叠；入场/出场/缴费与车位状态在同一事务中联动。脚本末附有实现说明。

## 6. 与需求模型的一致性

- 表名、字段名、类型、约束与《01_需求与数据库模型.md》第 3、6 节完全一致，可直接用于报告中“物理结构设计”表格；
- 字段与实体一一对应，无拆分、无合并，8 张表顺序为按外键依赖排列，与模型中的实体编号一致；
- 样例数据同时满足全部 CHECK、唯一和外键约束，并覆盖在场/已出场、临停/月租、已支付/已退款等状态。
